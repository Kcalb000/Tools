如何优雅的将文字, 信息,思想放进 PDF

适用对象： 研究人员、开发者、硬件/软件工程师、技术写作者，以及需要交付可审查、可复现、可出版文档的团队。 核心原则： 内容正确优先于外观；结构化源文件优先于一次性排版；目标期刊、客户或法规的现行要求优先于本指南。 适用范围： 学术论文、工程技术报告、设计说明书、应用笔记（Application Note）、元器件手册（Datasheet）及其图表、原理图、波形图和控制框图。

专业文档不是“把文字放进 PDF”。它是一个可验证的工程交付物：读者应能辨识结论、追溯依据、理解符号、检查数据，并在需要时重新生成图表和版面。工具本身不会自动带来专业性；正确的文档类型、统一的样式系统、受控的源文件和严格的发布检查才会。

1. 先选工作流，不先选排版软件

先回答四个问题，再决定工具：

  1. 谁是读者？ 审稿人、电路设计/应用工程师、现场工程师、客户，还是维护团队？
  2. 交付什么？ 一篇独立技术文章、持续维护的产品文档、上百页手册，还是一个受控的数据表系列？
  3. 版式与复用的复杂度多高？ 是否有双栏公式、数百个交叉引用、多产品共用段落、寄存器表、修订标记和多语言发布？
  4. 谁负责更新与批准？ 个人、研究课题组、小团队，还是需要审核、版本、权限和翻译工作流的组织？

1.1 三类成熟工作流

工作流典型源文件适合对象核心优势不适合的情况
论文排版工作流LaTeX、期刊模板、.bib、图源学术论文、会议投稿、数学/公式密集报告引用、公式、编号、交叉引用稳定，可版本管理需要大量非技术作者实时视觉编辑的文档
轻量技术写作工作流Markdown/AsciiDoc + 图源 + CIREADME、设计说明、软件文档、小型团队手册简洁、易审阅、适合 Git复杂书籍版式、严格分页、复用与合规要求很高的数据表
结构化出版工作流DITA/XML + CCMS + 发布模板产品文档、应用笔记库、手册系列、企业知识库内容复用、单一来源、多格式发布、审核与翻译一次性、篇幅短的个人文档

关键判断： Markdown 是优秀的轻量源格式，而不是工业排版系统。若文档需要严格分页、复杂表格、受控内容复用、变更条、产品变体和多渠道发布，应使用结构化创作和出版流水线，而不是依赖 Markdown 转 PDF 的偶然效果。

1.2 单一来源发布（Single Sourcing）

同一事实只保留一份受控源：型号名称、绝对最大额定值、引脚描述、订购信息、警告语和寄存器定义不应在多个文档中手工复制。通过变量、条件文本、内容引用和发布配置，按产品、修订版、语言或输出介质生成不同交付物。

这对数据表尤其重要：一处参数变更必须能够定位到所有引用它的 PDF、HTML、应用笔记和产品页。

2.2 工具不是标准

不要因为某个文件来自 KiCad、Visio、LaTeX 或 InDesign，就假设它符合行业标准。标准性来自于：

  • 采用正确的符号、单位、术语和参考标号；
  • 使用经核验的制造商数据、原理图和测试记录；
  • 以目标发布方的模板和提交规则为准；
  • 经过同行或工程审核；
  • 保留可以追溯的源文件与修订记录。

3. 学术论文与顶级期刊投稿

3.1 先获取目标刊的官方模板

每个期刊或会议都有自己的作者指南，页面尺寸、双栏规则、参考文献样式、图表格式、补充材料和匿名要求可能不同。不要从第三方网站随意复制模板，也不要把一个会议模板用于另一个期刊。

对 IEEE 投稿，可从 IEEE Template Selector 选择对应刊物或会议的官方 LaTeX/Word 模板；其他出版社同样应从目标刊的 Author Instructions 页面取得最新版要求。

3.2 推荐的论文工程结构

paper/
├── main.tex                 # 主入口，只组织内容
├── sections/
│   ├── introduction.tex
│   ├── method.tex
│   ├── results.tex
│   └── conclusion.tex
├── figures/
│   ├── fig_architecture.pdf
│   └── fig_results.pdf
├── figure_source/
│   ├── plot_results.py
│   └── architecture.svg
├── data/
│   └── results.csv
├── references.bib
├── Makefile                 # 或 latexmk/CI 构建脚本
└── README.md                # 构建环境、数据来源与复现说明

将正文、参考文献、图形源和数据分开。生成的 PDF、辅助文件和临时文件不应成为唯一的工作副本。

3.3 论文写作和排版要点

  • 使用模板定义的标题、作者、摘要、关键词、章节和参考文献命令；不要手调字体、边距、行距或页眉来“看起来更好”。
  • 所有图、表、方程、节和文献都使用标签与交叉引用。禁止手写“见图 3”或“参考文献 [12]”。
  • 每个图表应有独立结论：图注说明对象、条件、单位、数据来源和关键符号；表注说明测试条件、缩写和统计含义。
  • 定量主张必须可追溯到实验、仿真、公开数据或推导。准确区分 measured、simulated、calculated 和 illustrative。
  • 统计结果要说明样本量、误差条含义、置信区间/标准差/标准误的定义，以及数据排除或处理规则。
  • 使用文献管理器维护 .bib 数据库；提交前核对 DOI、作者、题名、年份、卷期和引用格式。
  • 最终以目标期刊的 PDF 检查器、投稿系统预览和作者指南为准。

3.4 LaTeX 与 Word 的边界

LaTeX 特别适合公式、参考文献、复杂编号、双栏和可复现构建；Word 在期刊明确提供并要求 Word 模板、或多人必须使用修订模式共同编辑时同样合适。格式要求决定工具，不是个人偏好。

无论采用哪种工具，都应使用样式（Styles）而非手工加粗、空格、回车和 Tab 来模拟标题、缩进或编号。

4. 工程技术文档与团队协作

4.1 适合轻量文档的 Git 工作流

对于接口文档、架构说明、软件设计、实验记录和内部工程规范，可将 Markdown/AsciiDoc 置于 Git 中：

  • 正文、图源、脚本和数据一起评审；
  • 用 Mermaid/PlantUML 保存可读的文本化图源；
  • 用 CI 构建 HTML、PDF 或静态站点；
  • 用链接检查、拼写检查、文档构建检查阻止失效发布；
  • 对每个版本打标签，并记录兼容性与发布日期。

此工作流适用于内容结构较简单、可接受浏览器/渲染器差异的文档。重要图形应在发布前导出为稳定的 SVG/PDF/PNG，并在实际阅读环境中检查。

4.2 适合长期产品文档的结构化写作

当团队面对多个产品型号、反复复用的安全警告、寄存器描述、参数表、程序步骤和多语言交付时，采用 DITA/XML 与 CCMS（组件内容管理系统）通常更稳健。

常见工具角色如下：

角色工具示例作用
结构化编辑Adobe FrameMaker、oXygen XML Editor、XMetaL依照 Schema/DTD 创作受约束的 XML 内容
内容管理AEM Guides、Tridion Docs、MadCap IXIA 等 CCMS组件复用、版本、权限、审核、翻译与检索
发布引擎DITA Open Toolkit、Antenna House Formatter、厂商发布服务将结构化源稳定转换为 PDF、HTML5、EPUB 等
视觉模板样式表、PDF 模板、品牌资产库统一字体、页眉页脚、表格、警告和封面

DITA 的 topic 与 map 模型将概念、任务和参考信息拆分为可复用主题，再由地图组装为手册或产品页面。不要把“结构化”误解为把 Word 文件导出为 XML；它要求内容模型、模板、版本和发布流程共同受控。

4.3 文档中的工程事实

工程文档应显式区分：

  • 需求（shall）：必须满足的约束；
  • 设计（design）：当前实现如何满足需求；
  • 验证（verification）：以测试、分析、检验或演示证明结果；
  • 假设与限制（assumptions/limitations）：适用范围、环境、版本和未覆盖情形；
  • 示例（example）：帮助理解，不可被误读为完整规范。

避免“通常可用”“性能良好”“支持高速”等不可验证表述。给出条件、界限、版本、单位、测量方法和证据位置。

5. 元器件手册、数据表与应用笔记

5.1 数据表的目标不是“产品介绍”

数据表是工程决策依据，应让读者在不依赖销售材料的情况下判断：器件能否在指定条件下安全、稳定、可重复地工作。数据表中的数字、条件和术语必须互相一致，并可追溯到批准的测试/仿真记录。

5.2 推荐的信息架构

以下结构适合大多数模拟、数字、混合信号和功率器件；具体顺序应服从企业模板与产品类型。

  1. 文档控制：标题、料号、修订版、发布日期、版权/保密等级
  2. 概述：产品定位、简短特性列表、典型应用
  3. 功能框图与封装/引脚图
  4. 引脚功能、引脚类型、未用引脚处理与散热焊盘说明
  5. 订购信息、封装选项、标记规则与环保/合规信息
  6. 绝对最大额定值（Absolute Maximum Ratings）
  7. 推荐工作条件（Recommended Operating Conditions）
  8. 电气特性表：最小值、典型值、最大值、单位、测试条件、脚注
  9. 时序/交流特性、开关特性或典型性能曲线
  10. 功能描述、状态表、真值表、时序图、寄存器说明（如适用）
  11. 应用信息：典型电路、布局、去耦、热设计、EMI/ESD 注意事项
  12. 封装机械尺寸、焊接/存储信息或对其权威文件的引用
  13. 修订历史和法律声明

5.3 绝对最大额定值不等于工作规格

必须明确区分：

  • 绝对最大额定值： 超过可能导致永久损伤的边界，不能当作常规工作点；
  • 推荐工作条件： 保证功能/规格所允许的工作范围；
  • 电气特性： 在表中列明的测试条件下测得或保证的参数；
  • 典型特性曲线： 用于理解趋势，除非明确说明，否则不应被表述为逐台保证值。

每一行参数都要包含足够的信息：参数名、符号、最小/典型/最大值、单位、温度/电压/负载/频率等条件、必要脚注，以及保证或表征性质。没有条件的“典型值”通常没有工程意义。

5.4 数据表与应用笔记的图形来源

内容首选来源不建议的做法
引脚图、封装图经批准的封装/机械数据库手工重绘后不核对引脚号和尺寸
原理图EDA 原生工程导出的受控图截图或用演示软件临时拼接
曲线与表格原始测试数据、仿真数据和可复现脚本在图像编辑器中手工改曲线
时序图/状态图经过评审的协议或 RTL/验证规范把概念时序图当成保证时序
控制框图经设计审核的系统架构用装饰性图标替代接口和信号含义

5.5 受控发布建议

对正式发布的数据表，至少应建立以下控制：

  • 文档编号、产品/硅版本、修订号、发布日期和变更摘要；
  • 参数表、引脚表和订购信息的唯一权威来源；
  • 技术、质量、产品和法务（若适用）的批准责任；
  • 发布前的数字、单位、交叉引用、图号、封装和料号核对；
  • 旧版本归档、撤回和客户可见性规则；
  • 可机器读取的原始表格数据，避免把 PDF 当作唯一数据库。

6. 国际标准、符号与单位

6.1 标准的使用原则

标准需按合同、地区、行业和发布要求选择；不可把某一标准说成适用于所有电路图或所有产品。以下是常用的权威起点，而非完整合规清单：

主题常用标准/机构在文档中的用途
电气图形符号IEC 60617电工和电子图中的图形符号数据库
系统与设备参考标识IEC/ISO 81346 系列系统、产品和部件的参考代号结构
国际单位制BIPM SI Brochure单位、词头、量和单位书写
PCB 封装与焊盘IPC-7351 系列及企业封装规范表面贴装焊盘/封装库设计
半导体产品要求JEDEC、AEC-Q、IEC/ISO 或客户规范依器件类别定义可靠性、测试、标识等要求

购买或引用标准时应使用其现行版本，并核实授权范围。标准库提供的符号不替代产品专用引脚定义、应用限制或 EDA 电气规则检查。

6.2 原理图符号与参考标号

在同一份文档或项目中保持一致：

  • 电阻：R1、R2；电容：C1；电感：L1；二极管：D1；
  • 晶体管/离散 MOSFET：Q1（企业规范可能另有定义）；
  • 集成电路：U1 或企业定义的前缀；
  • 连接器：J1；测试点：TP1；保险丝：F1；开关：SW1；
  • 运放、比较器、SR 触发器等通常作为其所在 IC 或逻辑单元的功能符号，而不是仅凭名称猜测引脚和极性。

必须显示或明确引用以下信息：参考标号、关键数值/料号、引脚编号、网络名、极性、电源/地、逻辑有效电平和连接点。导线交叉时使用清晰连接点；避免四向交叉让读者猜测是否连通。

6.3 SI 单位和数字格式

  • 数值与单位之间留一个空格：10 kΩ、3.3 V、25 °C、1 µs；百分号通常写作 10 %，但以目标期刊样式为准。
  • 单位符号不加复数：10 V，不是 10 Vs。
  • 区分大小写：m（milli）与 M（mega）、pF 与 PF、Hz 与 hz。
  • 使用标准 µ（micro）或在工具链不可靠时统一采用 u，但不得混用。
  • 变量以斜体、单位以正体是许多科技排版的常见约定；具体服从目标模板。
  • 有效数字应与不确定度和测量能力匹配。不要报告超过数据支撑精度的尾数。

7. 图、表、原理图与波形图

7.1 一张图只承担一个主要任务

读者的问题合适图形必须清楚表达
哪些元件电气连接？原理图元件、引脚、网络、方向、连接关系
系统由哪些功能组成？控制/系统框图功能边界、接口、数据或控制流向
信号何时变化？数字时序图基准时间、边沿、有效窗口、总线值、条件
模拟信号实际如何变化？数据曲线/波形图坐标轴、单位、范围、采样/处理、误差
消息和操作顺序是什么？序列图参与者、消息方向、顺序、条件、同步语义

不要用装饰性框图代替可复现的原理图；也不要把序列图误读为量化时序保证。

7.2 原理图

首选工具： KiCad、Altium Designer、OrCAD Capture 等 EDA 工具。用于论文或说明性插图时，Schemdraw 可生成可版本控制的图，但不应替代正式电气设计与 ERC 检查。

原理图要求：

  • 主信号流通常从左到右、从上到下；相关功能分组；
  • 明确电源、地、输入、输出、反馈与关键测试点；
  • 用网络标签减少长线和交叉，但标签必须一致；
  • 核对极性、引脚号、单位、多单元器件和电源单元；
  • 对正式设计运行 ERC，并用网表/PCB/制造商数据复核；
  • 从矢量源导出 SVG/PDF，避免屏幕截图。

7.3 波形、曲线和统计图

首选工具： Python + Matplotlib、MATLAB、Origin、LabVIEW 或经过验证的仿真/测试软件。

  • 坐标轴必须有物理量和单位，例如 Voltage (V)、Time (µs)；
  • 曲线用图例或直接标注，说明测量/仿真条件；
  • 对比图使用一致坐标尺度；不同尺度必须显著标注；
  • 说明滤波、平均、插值、归一化和数据截取；
  • 误差条要定义为标准差、标准误、置信区间或其他量；
  • 生成脚本、原始数据和固定随机种子（若适用）应可追溯。

7.4 数字时序图

首选工具： WaveDrom、GTKWave（从仿真波形导出）、EDA 验证工具；概念图可用 Inkscape 完成最后标注。

  • 标明时间单位或明确标为“非按比例的概念图”；
  • 清楚表达 active-low 信号（上划线、_n 后缀或文字说明）；
  • 必要时标出 setup、hold、propagation delay、采样边沿和 valid window；
  • 总线值放在有效区间中部；X、Z、don't care 的图例应统一；
  • 概念图不能冒充测试结果或数据表保证时序。

7.5 控制框图和序列图

框图： 用 Inkscape、Visio、diagrams.net 或企业图形模板制作。箭头必须有方向和含义，方框表示功能边界而非装饰。接口应标明名称、位宽、协议、时钟域或关键约束（按读者需要取舍）。

序列图： Mermaid 或 PlantUML 适合文本化、版本化的协议文档；用 alt、opt、loop 和同步/异步箭头表达逻辑，不要用它替代实测延迟或状态机。

7.6 表格

表格是数据表中最容易产生发布事故的部分：

  • 每列标示物理量、符号和单位；单位不重复塞进每个单元格；
  • 测试条件应紧邻参数，或由清晰列/脚注引用；
  • 最小、典型、最大值不得错位；—、N/A、空白和 TBD 的含义应明确；
  • 避免合并单元格过多，保证 PDF、HTML、屏幕阅读器和表格导出可读；
  • 将源数据保存在 CSV、数据库或受控表格中，版面表格只是一个发布视图。

8. 元器件模型、符号和封装库

8.1 获取顺序：制造商优先，库文件其次

对运放、比较器、SR 触发器、电容、MOSFET、三极管及其他器件，建议按以下顺序获取资料：

  1. 制造商官网的最新数据表、封装图、IBIS/SPICE/Verilog-A 模型和参考设计。
  2. 制造商官方 EDA 库，并确认器件修订、封装与数据表一致。
  3. EDA 工具的官方库，例如 KiCad 官方库。
  4. SnapEDA 与 Ultra Librarian 等第三方库，用于提高覆盖率。
  5. 自建并经过内部审核的库。

第三方库是起点，不是批准依据。下载后仍必须核对符号引脚号、引脚类型、封装焊盘、3D 模型、引脚 1 标识、间距、散热焊盘和制造商数据表版本。

8.2 按资源类型选择来源

需要的资源推荐来源必做验证
通用图形符号IEC 60617 或企业批准符号库适用标准、符号方向和语义
具体 IC 的符号/封装制造商、KiCad 官方库、第三方 CAD 库型号、封装、引脚号/名、NC/EP 引脚
SPICE 模型制造商模型与模型说明仿真器兼容性、模型范围、温度/工艺假设
IBIS 模型制造商引脚映射、版本、驱动/负载条件
FPGA/数字 IP 符号器件/EDA 厂商与项目规范电源域、配置脚、逻辑电平、版本
机械封装尺寸制造商封装图、批准的封装库单位、公差、焊盘建议、修订版

8.3 库审核清单

  • 型号、后缀、封装名称和数据表修订版完全匹配。
  • 符号的每个引脚号、名称、方向和电气类型已对照数据表。
  • 多单元器件、隐藏电源脚、裸露焊盘和 NC 引脚已正确处理。
  • Footprint 的引脚 1、焊盘编号、间距、孔径/形状和热焊盘正确。
  • 3D 模型仅用于可视化，不替代机械图审核。
  • 已运行 ERC/DRC，并完成原理图到 PCB 的网表一致性检查。
  • 库文件的来源、版本、许可证和审核人可追溯。

9. 排版、字体、图片与 PDF 交付

9.1 样式先行

建立并锁定以下样式，而不是手工调整每一段：

  • 正文、标题 1–3、图注、表注、代码、引用、警告、列表；
  • 图表编号、交叉引用和脚注；
  • 表头、单位行、交替底纹（如有）；
  • 颜色、线宽、箭头、面板标签和品牌元素。

一个专业模板应使内容作者只负责语义层次；他们不需要反复决定字号、段前距和编号格式。

9.2 字体和数学公式

  • 优先使用目标期刊、企业品牌或发布系统指定字体。
  • 正文、图注、表格和图内文字使用有限、统一的字体族；图中的字体必须在最终尺寸可读。
  • 发布前检查 PDF 是否嵌入字体、是否发生替换、数学符号是否损坏。
  • 数学公式使用 MathType、LaTeX 数学模式或编辑器内建公式功能；不要用截图、普通字符或手工空格伪造公式。
  • 变量、向量、矩阵、函数和单位的排版规范必须在全文一致，并服从目标模板。

9.3 图片格式

类型优先格式原因注意事项
原理图、框图、曲线、时序图、文字密集图SVG、PDF、EPS（仅在要求时）矢量缩放清晰检查字体嵌入、裁剪框、透明度和投稿系统兼容性
照片、显微图、热像图TIFF、PNG 或期刊指定格式保留像素数据按最终印刷尺寸与期刊要求导出
网页或演示图SVG、PNG浏览器兼容性较好不将低分辨率截图用于印刷
复合多面板图各面板保留原始源，最终用 PDF/SVG 组装可追溯、易修改面板字号、线宽、坐标尺度统一

不要将 JPEG 用于线条、文本和原理图；压缩伪影会损害边缘和小字。DPI 不是质量保证：像素尺寸、最终物理尺寸、内容类型和投稿系统要求共同决定是否合格。

9.4 版面质量控制

  • 在最终栏目宽度/纸张尺寸检查图表，而不是只在大屏幕上放大查看。
  • 检查页码、目录、页眉页脚、孤行/寡行、表格跨页、图表浮动、裁切和链接。
  • 导出后在独立 PDF 阅读器中检查：字体、颜色、透明度、超链接、书签、图层和打印效果。
  • 需要长期归档时，遵守接收方要求的 PDF/A 级别；不要自行假定所有 PDF/A 配置都适用。
  • 使用印刷或灰度预览，确保颜色不是唯一编码方式。

10. 可复现、评审与版本管理

10.1 推荐目录

technical-document/
├── source/                  # LaTeX、DITA/XML、Markdown 或其他正文源
├── figures/
│   └── final/               # 受控的发布图
├── figure_source/           # .kicad_sch、.svg、.mmd、.puml、绘图脚本
├── data/                    # 原始/处理后数据；附 README 描述来源
├── libraries/               # 经批准的符号、封装或模板（注明来源和许可）
├── build/                   # 可再生输出；通常不作为唯一源
├── scripts/                 # 构建、转换和检查脚本
├── CHANGELOG.md
└── README.md

敏感测试数据、未发布设计、许可证受限模型和客户资料必须放在符合访问控制要求的位置；不要因为“方便复现”而提交到公开仓库。

10.2 审核分层

审核层应检查的内容推荐审核者
技术审核电路、推导、数据、条件、结论和风险领域工程师/研究合作者
文档审核结构、术语、交叉引用、歧义、可读性技术写作者或非作者读者
图形审核符号、单位、可读性、颜色、最终尺寸图表作者 + 独立审阅者
发布审核模板、文件格式、版权、版本、批准记录文档负责人/发布负责人

不要让同一个人只看版面就批准全部内容。视觉正确不代表电气、统计或法规正确。

10.3 自动化检查

可用 CI 自动执行以下低风险检查：

  • 构建 LaTeX/DITA/站点并使构建失败可见；
  • 检查未解析的交叉引用、缺失图文件和失效链接；
  • 对文档源进行拼写、术语、Markdown/代码块格式检查；
  • 生成图表并检测工作区是否有未提交的生成差异；
  • 对 CSV/表格执行范围、单位或列完整性校验；
  • 为 PDF 输出页数、文件名、版本和元数据报告。

自动化不能取代对测试条件、器件参数、原理图连通性和科学结论的人工专业审核。

11. 发布前检查表

内容与证据

  • 读者、适用范围、版本和关键结论清楚。
  • 每项技术主张都有可定位的设计、测试、仿真、推导或权威来源。
  • 已区分保证值、典型值、仿真值、测量值和示意图。
  • 假设、限制、环境条件和例外已明确。

符号、单位与图表

  • 符号、参考标号、缩写、变量和术语全文一致。
  • 数值、单位、有效数字和温度/电压/负载条件正确。
  • 原理图的引脚、极性、网络、连接点和料号已与权威源核对。
  • 图表在最终尺寸仍清晰；坐标轴、图例、图注和面板标识完整。
  • 不依赖颜色传递关键语义；灰度/打印预览可理解。

数据表与产品资料

  • 绝对最大额定值、推荐工作条件和电气特性没有混淆。
  • 表格的 Min/Typ/Max、单位、脚注和测试条件无错位。
  • 引脚表、封装图、订购信息和料号与当前批准版本一致。
  • 修订历史准确说明了面向读者的实质变化。

文件与发布

  • 使用了目标期刊、客户或组织的当前模板和提交要求。
  • PDF 已独立打开检查；字体、图像、链接和裁切正常。
  • 源文件、数据、图源、脚本和第三方资产许可证可追溯。
  • 机密、个人信息、内部路径、批注和隐藏图层已清除或按策略保留。
  • 已完成规定的技术、文档和发布批准。

12. 权威资源

写作、模板与结构化出版

  • IEEE Author Center — Article Templates：IEEE 期刊文章模板与作者工具。
  • IEEE Template Selector：按具体出版物选择官方模板。
  • Adobe FrameMaker — Structured Authoring with DITA：DITA 结构化创作入口。
  • DITA Open Toolkit：开源 DITA 发布工具链。
  • oXygen XML Editor：XML/DITA 创作与验证工具。

标准、符号与单位

  • IEC 60617：电工/电子图形符号数据库。
  • BIPM — SI Brochure：国际单位制权威指南。
  • IEC Webstore 与 ISO Standards：查找适用标准的官方入口。
  • JEDEC Standards：半导体相关标准和出版物入口。

图形、EDA 与器件库

  • KiCad 与 KiCad Libraries：开源 EDA 工具及官方符号/封装库。
  • KiCad Documentation：原理图、库和 PCB 工作流文档。
  • SnapEDA：第三方 CAD 符号、封装和模型库。
  • Ultra Librarian：第三方元器件 CAD 库。
  • Schemdraw：用于可复现说明性电路图的 Python 库。
  • WaveDrom：文本化数字时序图。
  • Mermaid 与 PlantUML：文本化框图、流程图和序列图。
  • Inkscape：矢量图编辑与多面板图组装。
最终原则： 专业性来自可验证的内容、明确的符号、受控的源文件和稳定的发布流程。先让读者不必猜测，再让版面足够精致；先保证可追溯，再追求自动化。
